# Designing the Apple apps

Where to look before drawing or building a screen of the iPhone or Mac app. System parts (menus, sheets, tab bars, toolbars, pickers) are copied from Apple's sources, never drawn from memory; the content (cards, timeline, subtask branches) keeps the plugin's own metrics from `README.md`.

- [Human Interface Guidelines](https://developer.apple.com/design/human-interface-guidelines/): how every system component looks and when to use it. Most often needed: [Menus](https://developer.apple.com/design/human-interface-guidelines/menus), [Context menus](https://developer.apple.com/design/human-interface-guidelines/context-menus), [Materials](https://developer.apple.com/design/human-interface-guidelines/materials) (Liquid Glass), [Tab bars](https://developer.apple.com/design/human-interface-guidelines/tab-bars). The HTML pages may come back empty to a fetch; the same page as JSON is at `https://developer.apple.com/tutorials/data/design/human-interface-guidelines/<page>.json`.
- [Apple Design Resources](https://developer.apple.com/design/resources/): Apple's official UI kits for Figma and Sketch (iOS 26, macOS 26 and newer), with every system component, text style and colour.
- [Liquid Glass](https://developer.apple.com/documentation/TechnologyOverviews/liquid-glass): the iOS 26 design language in Apple's documentation.
- WWDC25 [Get to know the new design system](https://developer.apple.com/videos/play/wwdc2025/356) and «Meet Liquid Glass» (WWDC25): what changed in iOS 26 and why.
