# Quick Add Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tasks are typed in place in the lists: Enter gives the next one under it, indent makes a subtask, a draggable plus puts a new task anywhere, a bar over the keyboard sets priority and place; the task sheet goes away.

**Architecture:** One new service call `createAt` writes a task at an exact place. The UI keeps where the field stands as the drag's own `ListPlace`, so the plus, indent and drop share `placeAt`/`resultOf`. A `QuickEntry` state machine (no DOM) owns the entry; `TaskList` and `Timeline` draw the field; `QuickBar` draws the bar and its panels from the menu's `tileGroup` and `MonthPicker`.

**Tech Stack:** TypeScript, Obsidian plugin API, Vitest (`npm test`), esbuild (`npm run build`).

**Spec:** `docs/superpowers/specs/2026-11-01-quick-add-design.md`; look: `docs/design/README.md` § «Быстрый ввод», boards `docs/design/canvas/QuickFlow1–7.dc.html` → `QuickAdd.dc.html`.

## Review Focus

- Five Enters in a row faster than the file writes: all five tasks land in typed order at the field's place, none lost, no StaleTaskError. (Task 6 test `queues rapid enters in order`.)
- Indent at the first card of a list, right under a section header, or under a card already one level deeper: no move, button greyed. (Task 3 tests.)
- Plus dropped outside any list or timeline, or the drag cancelled by the system: nothing created, plus back. (Task 4 test `cancelled new drag returns null`.)
- Place panel → a column not on screen while text is typed: wheel turns, text and priority kept. (Task 6 test `moveTo keeps text and priority`.)
- Tap elsewhere while a write is still pending: the pending task still lands, the field closes. (Task 6 test `blur flushes the queue`.)

### Task 6: QuickEntry

**Files:** Create `src/ui/quick/QuickEntry.ts`, `src/ui/quick/WriteQueue.ts`; Test `tests/ui/QuickEntry.test.ts`

**Interfaces:**
- Consumes: `levelRange`, `shiftLevel`, `resultOf` (Task 3), `NewTaskPlace`, `createAt`, `edit` (Task 2).
- Produces:
  - `type EntrySpot = { kind: "list"; column: ListColumn; place: GapPlace } | { kind: "slot"; slot: Slot } | { kind: "stack"; parent: TaskKey }`.
  - `interface EntryState { spot: EntrySpot; text: string; priority: string | null; pending: readonly string[]; renaming: TaskItem | null; canIndent: boolean; canOutdent: boolean }`.
  - `interface QuickEntryDeps { cards(column: ListColumn): readonly PlacedCard[]; placeOf(column: ListColumn, result: PlaceResult): NewTaskPlace; fresh(): Promise<void>; createAt: TaskService["createAt"]; edit: TaskService["edit"]; placement(spot: EntrySpot): Placement; onChange(state: EntryState | null): void }`.
  - `class QuickEntry { open(spot: EntrySpot, renaming?: TaskItem): void; get state(): EntryState | null; type(text: string): void; setPriority(prefix: string | null): void; indent(delta: 1 | -1): void; enter(): void; blur(): void; escape(): void; moveTo(spot: EntrySpot): void }`.
  - `class WriteQueue { push(job: () => Promise<void>): void; idle(): Promise<void> }` — one job at a time, in order.
- Rules (spec §4.3–4.8, §5.1): Enter with text → `pending.push(text)`, field stays at `place` (drawn after the pending), queue `await fresh(); createAt(text, priority, placeOf(column, resultOf(cards(column), place)))`, then `place.index += 1`, `pending.shift()`; priority resets to null for the next field. Empty Enter: level > 0 → `shiftLevel(-1)`; else close. Blur: queue the text if any, close. Escape: drop own text, close. Slot spot: Enter creates and closes. Rename: Enter → `edit` then open an empty entry under it (first subtask when it has subtasks); blur → `edit` only; empty text → cancel.
