# Поиск задачи — план

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** поиск задач по названию и описанию с переходом к найденной карточке, колонка Done, капсула отмены и лупы.

**Architecture:** совпадения считает домен (`src/domain/search.ts`), сервис отдаёт `SearchHit` и список Done через `contracts.ts`; UI рисует окно поиска (телефон — слой с полем над клавиатурой, Mac — панель по центру), капсулу нижнего ряда и временное место экрана «done» левее Inbox.

**Tech Stack:** TypeScript, Obsidian API, vitest (happy-dom), CSS-токены `styles.css`.

**Spec:** `docs/superpowers/specs/2026-11-05-search-design.md`

## Global Constraints

- `ui` импортирует только `application`; страж `tests/architecture.test.ts` зелёный.
- `contracts.ts` только добавляется; `settings.ts` (`RightMode`) не меняется.
- Каждое значение в CSS — токен `--tc-…` в блоке `body { … }`, светлые — в `body.theme-light`; `tests/styles.test.ts` зелёный, `DESIGN` в `src/ui/design.ts` согласован.
- Новый метод `TaskService` есть и в `tests/fakes/DemoTaskService.ts`; `npm run build:demo` зелёный.
- Тексты UI английские: «Search tasks», «Cancel», «No tasks found», «Search».
- Перед релизом — проверка в тестовом Obsidian: телефон и окно Mac, светлая и тёмная.

## Review Focus

- Запрос из пробелов — не ищет ничего (пустой экран), а не «всё».
- Регистр и «ё»: «ЁЛКА» находит «елка» и наоборот; кусок для подсветки берётся из исходного текста той же длины.
- Ссылки в названии: ищем по видимому тексту (`plainText`), `[[Note|alias]]` находится по «alias», не по «Note».
- Задача в Done с подзадачами и выполненная подзадача открытой задачи: карточки последней на экране нет — в результатах её нет (ищем только то, что экран рисует: задачи и их открытые подзадачи).
- Экран в положении «done», затем файл поменялся или настройки перерисовали кадр: экран остаётся на Done, а не прыгает на сохранённое положение.

### Task 1: Совпадения в домене и сервисе

**Files:**

- Modify: `src/application/contracts.ts`, `src/application/TaskServiceImpl.ts`, `tests/fakes/DemoTaskService.ts`, `tests/application/TaskServiceImpl.test.ts`

**Interfaces:**
- Produces (domain): `findIn(text: string, query: string): { start: number; end: number } | null` — первое вхождение без учёта регистра, «ё»≡«е», индексы в исходной строке; пустой/пробельный запрос → `null`.
- Produces (contracts): 
  ```ts
  export interface TitlePart { readonly text: string; readonly match: boolean }
  export interface SnippetParts { readonly before: string; readonly match: string; readonly after: string }
  export interface SearchHit { readonly item: TaskItem; readonly title: readonly TitlePart[]; readonly description: SnippetParts | null }
  // TaskService:
  doneView(): Promise<readonly TaskItem[]>;
  search(query: string): Promise<readonly SearchHit[]>;
  ```
  `title` пуст, если в названии не найдено. Порядок хитов: секции inbox, backlog, soon, now, done; внутри — порядок файла, задача перед своими подзадачами. Обходятся задачи секции и их открытые подзадачи на любой глубине (как `toItem` рисует). Название — `plainText(text)` после снятия приоритета. Описание — строки `descriptionMarkdown`, склеенные пробелом, без маркеров списка `- `, пробелы схлопнуты; `before` — не больше 24 символов перед совпадением (обрезан по слову, с «…» спереди, если обрезан), `after` — остаток.

- [ ] **Step 1:** тесты `findIn`: `findIn("Ёлка", "елка")` → `{0,4}`; `findIn("Продлить загранпаспорт", "ПАСПОРТ")` → `{14,21}`; `findIn("x", "  ")` → `null`.
- [ ] **Step 2:** тесты сервиса на файле с Inbox/Backlog/Soon/Now/Done, подзадачей и описанием: `search("паспорт")` даёт хиты в порядке секций; подзадача — свой хит с `item.isSubtask`; задача с совпадением в названии и описании — оба поля непусты; совпадение только в описании — `title` пуст, `description.match === "паспорт"`; выполненная подзадача открытой задачи не найдена; `[[Note|alias]]` находится по «alias»; `doneView()` — задачи Done в порядке файла.

**Interfaces:**
- Produces: в `screens.ts` `export type Place = RightMode | "done"`, `placeIndex(place: Place): number` (done → -1, иначе `PLACES.indexOf`); `stepScreen` принимает `Screen` с `mode: Place`: из done шаг +1 → inbox, шаг -1 → `null`; из inbox шаг -1 → `null` (как сейчас).
- `DayData.done: readonly TaskItem[]` — читается вместе с остальными списками (`tasks.doneView()`).

- CSS: `.tc-done` — колонка списка с отступами левой колонки, `left: calc(-1 * (var(--tc-half-column) + var(--tc-divider)))` при `is-inbox`, дальше левее в остальных местах (по образцу `.tc-inbox`); `.tc-head.is-done` заголовок с именем `sections.done`; разделитель `.tc-divider.is-fixed.is-done` между Done и Inbox. - Свайп/колёсико/стрелки из done ведут на inbox и сбрасывают `shownPlace`.
