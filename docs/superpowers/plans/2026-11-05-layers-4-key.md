# Блок 4 «Непрозрачный TaskKey» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** UI не разбирает `TaskKey` на поля. Какие поля составляют личность задачи, решают функции в `application/taskKeys.ts`, которые реэкспортируют контракты: `samePlace` (место в файле, без `raw`), `sameLine` (строка как прочитана), `sameTaskTree` (одна задача списка вместе с подзадачами: секция и номер, путь не в счёт), `keyId` (строка для выбора). `TaskItem` получает `list` (в каком списке задача) и `isSubtask`. Поведение, вид, `data.json` и формат файла — те же: каждое сравнение отвечает в каждом месте вызова ровно так же, как сейчас.

**Architecture:** `application/taskKeys.ts` — четыре чистые функции над `TaskKey`; `contracts.ts` их реэкспортирует. Сервисное `sameKey` остаётся внутри `TaskServiceImpl` и собирается как `samePlace && sameLine` (тот же ответ). `toItem` заполняет `list` и `isSubtask` из записи; `DemoTaskService` — из своего ключа. UI берёт сравнения из контрактов, `item.list` вместо `item.key.section`, `item.isSubtask` вместо `key.path.length > 0`.

**Tech Stack:** TypeScript, vitest + happy-dom, esbuild, Obsidian (тестовый, CDP).

**Spec:** `docs/superpowers/specs/2026-11-05-layers-4-key-design.md`, обзор `2026-11-05-layers-overview.md`.

## Что в спеке уже не так (сверено с master e95efc0, после блока 3)

- **`sameTask` используют ещё `Timeline.ts`** (`:471`, `:500`, `:509`) и `QuickEntryController.ts` (`:388`), не только перечисленные в спеке. Все переходят на `samePlace`.
- **Ещё одна семантика: секция и номер без пути.** `Timeline.isSelected` (`:587`, выбранная долгим нажатием задача) и `TaskCalendarView.unnamed` (`:870`, карточка, ждущая имени секции) сравнивают `section` и `index`, но не `path`: подзадача считается вместе со своей задачей. Это не `samePlace` — чтобы ответы не поменялись, у неё своё имя `sameTaskTree`. Спека её не называет.
- **Имя `samePlace` в UI занято:** `drag/listPlace.ts` уже экспортирует `samePlace(a: GapPlace, b: GapPlace)` (тот же зазор). Оно переименовывается в `sameGap` (вместе с импортом в `tests/ui/listPlace.test.ts`; ожидания те же), чтобы `samePlace` значило одно.
- **`QuickEntry.landed`** ищет созданную задачу по месту **и** строке (`sameTask && raw`) — это сервисная семантика. UI собирает её из двух имён: `samePlace(a, b) && sameLine(a, b)`. `keyAt` (переименование) — `sameLine`. Асинхронный `refresh` не нужен.
- **`UNWRITTEN` и `ListCard.key: TaskKey | null`.** Фальшивый ключ нужен только `Run.shifted`, которому нужны лишь уровень и секция карточки (`shiftLevel` → `levelRange`). Вместо `TaskKey | null` (тогда `resultOf` и `gapOf`, где ключ всегда есть, получили бы лишние проверки на null) `levelRange`/`fitLevel`/`shiftLevel` принимают `LevelCard { level, group }`, а `ListCard extends LevelCard` с ключом. Ненаписанная строка — `LevelCard` без ключа; `UNWRITTEN` уходит.
- **Подзадача в `QuickEntryController.shownPlace`** — `renaming.isSubtask`, а не `parentText !== null`: `dayView.slotted` строит подзадачу со слотом через `toItem` без родителя, у неё `parentText` — null, а путь не пуст. `TaskCalendarView.sectionsHome` (`parentText !== null`) ключ не читает и не меняется.
- **`TaskItem.list`** читают `TaskCalendarView.ts` (`:830`, `:848`, `:857`) и `menu/quickMoves.ts` (`:18`, `:23`).
- **Строки стража не меняются:** блок не меняет импортов между слоями (`taskKeys.ts` — `application`, UI берёт его через контракты). Вычёркивать нечего.
- **Тестов `sameTask`/`keyId` нет.** Новые — в `tests/application/taskKeys.test.ts`; `toItem` (`list`, `isSubtask`) — в `tests/application/taskItems.test.ts`. Фикстуры `TaskItem` в тестах UI получают `list` и `isSubtask`, согласные с их ключом.

## Global Constraints

- Рефакторинг: ни вида, ни записи в файл, ни `data.json`, ни поведения не меняется. `docs/plugin/` не меняется.
- Перенос правила = перенос его тестов; ни одно ожидание не ослабляется и не пропускается.
- Контракты только добавляют: реэкспорт четырёх функций, `TaskItem.list`, `TaskItem.isSubtask`; поля — и в `tests/fakes/DemoTaskService.ts`.
- `ALLOWED` в страже — ровно оставшиеся нарушения.
- Стиль соседнего кода: табы, короткие английские doc-комментарии.
- `npm test`, `npm run build:demo`, `npm run build` (последней) зелёные; проверка в тестовом Obsidian (телефон и Mac, светлая и тёмная).
