# Блок 1 «Один разбор файла на изменение» — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** одно действие и одна перезагрузка задач разбирают файл задач один раз (эхо — ноль раз), регулярки маркеров компилируются один раз, diff отмены не строит квадратную матрицу.

**Architecture:** кеш регулярок в `TaskLine`; пакетная замена строк `TaskDocument.replaceAll` для правил нормализации и тегов; Майерс в `TextPatch`; `cachedRead` в store; в `TaskServiceImpl` — кеш последнего нормализованного документа по (текст, сегодня, объект настроек), который `mutate` заполняет результатом своей записи.

**Tech Stack:** TypeScript, vitest, Obsidian API.

**Spec:** `docs/superpowers/specs/2026-11-03-perf-1-data-design.md`

## Global Constraints

- Вывод (текст файла после любой операции и нормализации) байт в байт как до блока: все существующие тесты проходят без изменений ожиданий.
- Контракты `src/application/contracts.ts` и `src/settings.ts` не меняются.
- Слои: `domain` чистый, `ui` не трогаем в этом блоке.
- Комментарии — только где без них никак, стиль соседнего кода (английский, короткий JSDoc над классом/методом).
- Тесты: `npm test` (vitest), сборка: `npm run build`.

## Review Focus

1. Файл с `\r\n` и без завершающего перевода строки: кеш по тексту и посев из `mutate` дают те же представления, что свежий разбор.
2. Смена настроек (маркеры, названия секций, приоритеты) между двумя чтениями: кеш не отдаёт документ, разобранный по старым настройкам.
3. Переход через границу дня между двумя чтениями при том же тексте: кеш не отдаёт вчерашнюю нормализацию.
4. Два набора маркеров по очереди (смена маркера в настройках): кеш регулярок отдаёт правильный слайсер для каждого.
5. Отмена после действия, которое двигает задачу далеко (в «Сделано»): `revert` даёт ровно прежний текст, в том числе после чужой правки в другом месте файла.

### Task 5: Кеш нормализованного документа в сервисе

**Files:**
- Modify: `src/application/TaskServiceImpl.ts` (`readNormalized`, `normalize`, `mutate`)
- Modify: `tests/fakes/InMemoryTaskFileStore.ts` (счётчик `reads`)
- Test: `tests/application/TaskServiceImpl.test.ts` (новый `describe("one parse per version of the file")`)

**Interfaces:**
- Внутри `TaskServiceImpl`: приватное поле `normalized: { text: string; today: LocalDate; settings: TaskCalendarSettings; doc: TaskDocument; changed: boolean } | null`. `changed` — нормализация изменила текст (то, что сейчас `normalize()` проверяет сравнением с исходным документом).
- `readNormalized()` возвращает кешированный `doc`, если `text`, `today` и `settings` (по `===`) совпали; иначе разбирает, нормализует и кладёт в кеш.
- `normalize()` берёт ту же запись; пишет (через `mutate(d => d, false)`) только если `changed`.
- `mutate` после успешной записи кладёт в кеш `{ text: after, today, settings, doc: <документ, из которого сериализован after>, changed: false }`.

- [ ] **Step 1: Тесты** (`const parse = vi.spyOn(TaskDocument, "parse")`)
  - `await svc.normalize(); await Promise.all([svc.dayView(T), svc.soonWithoutDateView(), svc.inboxView()])` → `parse` вызван 1 раз.
  - Повтор того же набора без изменения текста → 0 новых вызовов.
  - `await svc.setStatus(key, "done")`, затем тот же набор чтений → 0 вызовов `parse` после записи; представления равны (`toEqual`) представлениям нового сервиса на том же тексте (свежий разбор). Повторить на тексте с `\r\n` и без последнего перевода строки.
  - `settings.update({ dueDateMarker: "@due" })` между чтениями → новый разбор, представление видит дату по новому маркеру.
  - Часы переходят через границу дня при том же тексте → новый разбор, просроченная задача показана на сегодня.
  - Внешняя правка `store.text = ...` → новый разбор, представление видит правку.
