# Источники встреч, фаза 2: приложение iPhone пишет календари телефона

Дата: 2026-11-05. Статус: черновик, ждёт Макса.

Стоит на фазе 1 (ветки `events-files` плагина и `meetings-from-files` приложения): встречи живут только в файлах волта, таймлайн и напоминания читают файлы, Google API пишет `calendar/google.json`, Scriptable — `calendar/work.json`.

## Зачем

Рабочий календарь (Exchange) приходит на Mac и в Obsidian только через Scriptable, а его запускают «Команды»: автоматизация при открытии Obsidian и раз в час днём, кнопка Refresh now. Приложение Task Calendar для iPhone само имеет доступ к календарям телефона и само просыпается (выход из Obsidian, фоновое пробуждение, кнопки уведомлений). Пусть оно пишет календари телефона в волт, молча и чаще. Scriptable и Google API остаются: если приложение просрочится (бесплатная подпись живёт 7 дней) или Google API откажет, встречи берутся из них без участия Макса.

## Цели

- Рабочий календарь обновляется приложением, без «Команд».
- Запасные источники подхватывают сами: просроченное приложение — Scriptable; отказавший Google API — календари Google из приложения.
- Ни один источник не затирает другой, встречи не «мигают» между версиями.
- Какие календари видны в плагине, решают только настройки плагина.
- Таймлайн и кнопка «After встреча» в напоминаниях видят одно и то же.

## Не цели

- Писать в календари (создавать или менять встречи).
- Склеивать одну встречу, которая лежит в двух разных календарях (приглашение и в Exchange, и в Google). Это разные календари, каждый показывается или прячется галочкой.
- Убирать Scriptable: он остаётся запасным, его настройка не меняется.

## Анти-цели (провал, даже если «работает»)

- «Команды» или приложение мелькают без нажатия Refresh now.
- Встречи календаря то появляются, то пропадают или прыгают между версиями от разных источников.
- Оранжевая точка горит, хотя на экране всё свежее (например, лишь потому, что приложение просрочилось, а Scriptable подхватил).
- Выбор календарей в Apple Calendar или в Google меняет то, что видно в плагине.

## Решения Макса

1. **У каждого источника свой файл.** Писатель кладёт туда все календари, которые видит, без отбора; чужие файлы не трогает.
   - `calendar/google.json` — Google API (плагин), все календари Google-аккаунта.
   - `calendar/iphone.json` — приложение Task Calendar, все календари телефона (Exchange, Google, если аккаунт добавлен в iPhone, iCloud и др.).
   - `calendar/work.json` — Scriptable, как сейчас (путь — настройка Work calendar → File path).
2. **Каждый календарь берётся целиком из одного файла.** Встречи одного календаря из разных файлов не смешиваются. Файл выбирается порядком источников для этого календаря: первый в порядке, кто видит календарь и свежий; если свежих нет — самый свежий из видящих.
   - Календари Google-аккаунта: Google API → приложение → Scriptable. Google API — из первых рук; телефон синхронизирует Google с задержкой, поэтому время записи файла приложением не значит, что его данные новее.
   - Остальные календари: приложение → Scriptable.
3. **Галочки календарей — в плагине, один список на все файлы**, по аккаунтам. Новый календарь, появившийся в файлах, сразу показывается. Текущий выбор (галочки Google, Work calendar → Calendars) переносится.
4. **Refresh now на iPhone** на мгновение открывает приложение: оно пишет свой файл и возвращает в Obsidian. Кнопка жмётся, когда горит оранжевая точка, и должна обновить всё, что может: Google API тоже запрашивается заново.
5. **Оранжевая точка** значит одно: что-то на экране устарело и само не обновилось, жми Refresh now. Какой источник подхватил — внутренняя кухня, видна только в окне источников.

## Как устроено

### Формат файлов

Все три файла — один формат (фаза 1), плюс поля:

```json
{
  "exportedAt": "2026-11-05T10:00:00.000Z",
  "device": "iPhone Макса",
  "from": "2026-10-06T00:00:00+07:00",
  "to": "2027-02-04T00:00:00+07:00",
  "validUntil": "2026-11-12T09:44:00.000Z",
  "events": [
    { "id": "…", "title": "Standup", "start": "…", "end": "…", "allDay": false,
      "calendar": "Календарь", "calendarId": "…", "account": "max@company.ru", "color": "#0A84FF" }
  ]
}
```

- `from`/`to` — какие дни файл покрывает. Писатель записывает окно, которое выгрузил: Google API и приложение — месяц назад и три месяца вперёд; Scriptable — со вчера на две недели (как сейчас). Файл без `from`/`to` (старый Scriptable до обновления плагина) покрывает дни своих встреч от первой до последней.
- `account` — аккаунт календаря: для Google API — почта вошедшего аккаунта (id его главного календаря); для приложения — `EKSource.title` и `EKSource.sourceType` (название аккаунта в iOS бывает «Gmail» или придуманным, не почтой — см. «Один календарь в разных файлах»). Scriptable аккаунта не знает (его API не даёт) и пишет `calendarId` — `EKCalendar.calendarIdentifier`, тот же, что видит приложение.
- `validUntil` — только у `iphone.json`: до какого момента действует подпись приложения (приложение её знает: `AppSignature.expiration`).
- Пустой календарь (без встреч в окне) тоже должен быть виден в списке галочек и в выборе файла. Поэтому у файла есть ещё список `calendars`: `[{ "calendar", "calendarId", "account", "color" }]` — все календари писателя, даже без встреч.

### Один календарь в разных файлах

Календарь — это пара «аккаунт + название». Как её получает каждый файл:

- `google.json`: аккаунт — почта Google-аккаунта, название — `summary` календаря.
- `iphone.json`: аккаунт Google в iOS узнаётся не по названию аккаунта, а по главному календарю: iOS называет главный календарь Google почтой аккаунта, поэтому аккаунт (`EKSource`), в котором есть календарь с названием, равным почте из `google.json`, — это Google-аккаунт, и его календарям ставится эта почта. Внутри него календари сопоставляются с `google.json` по названию. Остальные аккаунты — по своему `EKSource.title`. Это проверяется на телефоне Макса первым шагом реализации (приложение пишет, что видит); если iOS называет иначе — правило сопоставления меняется до остальной работы.
- `work.json`: по `calendarId` находится тот же календарь в `iphone.json` и берётся его аккаунт. Если `iphone.json` нет или там нет такого `calendarId` — аккаунт неизвестен, и календарь сопоставляется по одному названию, если среди известных календарей ровно один с таким названием; иначе это отдельный календарь «iPhone · название».

Календари Google-аккаунта — те, чей аккаунт равен почте аккаунта из `google.json` (для порядка источников в решении 2).

### Выбор файла для календаря на день

Для дня D и календаря K: кандидаты — файлы, которые видят K (он есть в их `calendars`) и покрывают D (`from` ≤ D < `to`). Из кандидатов в порядке решения 2 берётся первый свежий; свежий — `exportedAt` моложе Stale after (по умолчанию 3 часа). Свежих нет — самый свежий по `exportedAt`. Встречи K на день D берутся только из выбранного файла; цвет — тоже из него.

Свежесть считается только по `exportedAt` в файле — одинаково на всех устройствах и в напоминаниях; ошибка Google API на одном устройстве (например, без сети) файл не портит. Пока Google API здоров, плагин переписывает `google.json` не реже раза в 10 минут (фаза 1), так что отказ API виден по старению файла.

### Галочки

Настройка «скрытые календари»: список пар «аккаунт + название». Пустой — видно всё. Новый календарь не в списке — значит, виден (решение 3).

Перенос текущего выбора делается один раз и только на iPhone, когда есть и `google.json`, и `iphone.json` (только там сопоставление полное). До переноса на всех устройствах работают старые фильтры, как в фазе 1. После переноса в настройках ставится отметка «перенесено» (она приезжает на Mac через Sync вместе со списком):
- `google.calendarIds` не пуст → календари Google-аккаунта, чьих id нет в списке, скрываются.
- `workCalendarTitles` не пуст → скрываются календари, которые есть только в `work.json`/`iphone.json` (не в `google.json`) и чьих названий нет в списке. Календари Google не скрываются этим правилом: раньше они уходили из рабочего файла как дубли, теперь дублей нет.
- Старые настройки после переноса больше ни на что не влияют (удалить их из `settings.ts` — решение исполнителя вместе с командой, см. «Ограничения»).

Google API теперь выгружает все календари аккаунта, не только отмеченные (и не смотрит на `selected` из самого Google).

### Приложение iPhone

- Снова просит доступ к календарям (полный). В настройках приложения строка Calendar в Permissions с подписью, зачем.
- Пишет `calendar/iphone.json` в папку волта, которую ему выбрали (доступ на запись у него уже есть): все календари телефона, встречи с месяца назад на три месяца вперёд, без отменённых и тех, от которых Макс отказался (как Scriptable).
- Когда пишет: каждый раз, когда обновляет напоминания (выход из Obsidian через «Команды», фоновое пробуждение, кнопки уведомлений, открытие приложения), и по Refresh now. Если доступа к календарям нет — файл не пишется; если был — не трогается.
- Новое: автоматизация «при открытии Obsidian» тоже запускает Update Reminders (молча, как при выходе), чтобы файл был свежим к открытию календаря. Шаг в настройку «Команд» (документация).
- Refresh now: ссылка вида `taskcalendar://refresh` открывает приложение, оно обновляет напоминания и файл и открывает `obsidian://` обратно.
- Напоминания и кнопка «After встреча» берут встречи тем же выбором файлов и теми же галочками, через модуль плагина (фаза 1 уже читает файлы через него).

### Refresh now на iPhone

1. Плагин запрашивает Google API заново.
2. Если в `iphone.json` `validUntil` в будущем — открывает `taskcalendar://refresh`; приложение пишет файл и возвращает в Obsidian. Иначе (файла нет, подпись истекла) — сразу шаг 3.
3. Если после возврата `iphone.json` всё ещё не свежий (нет доступа к календарям, запись не удалась, подпись истекла) — запускает команду Scriptable, как сейчас. Так кнопка обновляет всё, что может.
4. Когда файлы изменятся, таймлайн перерисуется сам (файлы отслеживаются, фаза 1).

На Mac Refresh now как сейчас: запрашивает Google API и перечитывает файлы.

### Оранжевая точка и окно источников

- Точка горит, если на показанный день у какого-то видимого календаря выбранный файл не свежий (решение 5). Запасной источник, который подхватил свежим, точку не зажигает.
- Окно источников: по строке на каждый из трёх файлов — когда обновлялся и ошибка, если есть (как сейчас для двух). Как это выглядит — доска в Claude Design до реализации (см. «Что сделать»).

## Ограничения

- `src/settings.ts` и `src/application/contracts.ts` — общие контракты: менять только с согласия Макса; согласие на изменения ниже — это принятие этого спека. Нужно: настройка скрытых календарей и отметка «перенесено»; три источника вместо двух в `CalendarSource`/статусах.
- Работа начинается от master после того, как туда влиты фаза 1 и «layers 10: settings», если она к тому моменту готова; иначе — от master с фазой 1, а настройки сливаются с layers 10 при вливании.
- Слои плагина: выбор файла и галочки — чистая логика в `application` (или `domain`), её же вызывает модуль телефона `src/phone`. Чтение файлов — `infrastructure`.
- Приложение iPhone без своей логики про календари: что показывать, решает модуль плагина; приложение только выгружает EventKit в файл и передаёт тексты файлов модулю.
- Экран настроек со списком календарей и окно источников с тремя строками — экраны, которых нет в дизайне: сначала доски в Claude Design (обе платформы, тёмная и светлая), потом код.
- Документация: `docs/plugin/calendars.md`, `work-calendar.md` (Scriptable — запасной), `notifications.md` (доступ к календарю, автоматизация при открытии, Refresh now), `settings.md`, `agents.md`.

## Что решил я (Макс может поправить)

- Календарь — пара «аккаунт + название»; Scriptable сопоставляется через `calendarId`.
- Порог свежести — существующий Stale after.
- Окно `iphone.json` — как у Google: месяц назад, три месяца вперёд.
- Цвет встречи — из файла, откуда взят календарь (при переходе на запасной цвет может чуть смениться).
- Выбор файла делается на каждый день отдельно, с учётом окна файла: Scriptable покрывает только две недели вперёд и не может «перекрыть» дальние дни.
- Файлы получают список `calendars`, чтобы пустой календарь не пропадал из галочек и не путал выбор файла.
- Google-аккаунт в iOS находится по главному календарю, названному почтой; проверяется на телефоне первым шагом.
- Свежесть — только по времени записи файла: ошибки Google API на одном устройстве не влияют на выбор на других и в напоминаниях.
- Refresh now: если файл приложения после возврата всё ещё не свежий — дополнительно Scriptable.
- Перенос старого выбора — один раз, на iPhone, когда есть файлы Google и приложения; до этого — старые фильтры.
