# Этап 3. Кнопки и иконки — компоненты

Дата: 2026-11-04. Обзор этапов: `2026-11-04-design-overview.md`. Находки: `2026-11-04-design-audit.md`, разделы 2, 3, 7.

## Цель

В коде одна кнопка. Сейчас кнопку каждый раз собирают руками: элемент, `aria-label`, иконка, обработчик. Таких сборок около 12. После этапа кнопку создаёт компонент, а вид задаётся параметром. Иконки берутся из одного набора, а не из трёх фабрик с дублями.

**Пиксели и поведение не меняются.** Каталог экранов до и после совпадает попиксельно. Нажатия, жесты, `aria-label` и `title` те же.

## Решения

### 1. Папка `src/ui/kit/`

Общие объекты интерфейса. От остального `ui` их отличают два правила:
- они не знают про задачи и экраны;
- они импортируют только `dom.ts` и `design.ts`.

### 2. Иконки: `kit/icons.ts`

Сейчас три фабрики: `icons.ts`, `menu/menuIcons.ts`, `sources/sourceIcons.ts`, и мост `tileIcon`. Они сливаются в одну:
- **Одна карта путей.** `IconName` — объединение всех имён. Каждый рисунок записан один раз:
  - `cancel` и `cross` — одно имя, `cross`;
  - `description`, `section` и `plus` — по одной записи.
- **Одна функция** `icon(name: IconName, options?: { filled?: boolean }): SVGSVGElement`. Она умеет пути с заливкой: они есть у иконок меню.
- **Атрибуты не меняются.** `viewBox`, атрибуты и классы, которые сейчас ставят три фабрики, остаются как есть, чтобы CSS их находил. Если у фабрик были разные классы на `<svg>`, `icon()` берёт класс параметром.
- **Старые файлы удаляются.** Их импорты переводятся на `kit/icons.ts`.

### 3. Кнопка: `kit/Button.ts`

```ts
type ButtonKind = "round" | "icon" | "bar" | "text" | "pill" | "swatch";
type ButtonTone = "plain" | "accent" | "quiet" | "strong" | "danger";

interface ButtonSpec {
	readonly kind: ButtonKind;
	readonly tone?: ButtonTone;
	readonly label: string;          // aria-label, а у text/pill ещё и видимый текст
	readonly icon?: IconName;
	readonly text?: string;          // видимая подпись рядом с иконкой (место на полосе, кнопка вопроса)
	readonly title?: string;
	readonly cls?: string;           // класс назначения: tc-plus, tc-undo, tc-arrow… — CSS позиции и назначения
	readonly onPress: (e: MouseEvent) => void;
}

class Button {
	static create(parent: HTMLElement, spec: ButtonSpec): Button;
	readonly el: HTMLButtonElement;
	setOn(on: boolean): void;        // is-on
	setOff(off: boolean): void;      // is-off (отмене нечего отменять)
	setHidden(hidden: boolean): void;// is-hidden
	setText(text: string): void;
	setIcon(name: IconName): void;
}
```

Классы на элементе: `tc-btn is-<kind> is-<tone>` и класс назначения.

**Специфичность.** Правила пишутся как `button.tc-btn`, `button.tc-btn:hover`, `button.tc-btn:active`, а не голым `.tc-btn`. Это (0,1,1) и (0,2,1), не слабее нынешних контейнерных правил. Голый `.tc-btn` (0,1,0) проиграл бы кнопочным правилам Obsidian: вернулись бы `padding`, фон и тень. Тест в `styles.test.ts` проверяет, что у каждого правила `.tc-btn` в селекторе есть `button`. CSS этапа 1 уже держит общий сброс, круглую кнопку и нажатие группами селекторов. На этом этапе группы становятся классами:
- общий сброс → `.tc-btn`;
- круглая кнопка → `.tc-btn.is-round`;
- нажатие → `.tc-btn:active`;
- наведение и фокус (этап 2) → `.tc-btn`.

**iPad и касание телефона** (найдено на ревью этапа 2). Obsidian на iPad даёт кнопкам `.is-tablet button:not(.clickable-icon) { padding: 4px 20px }`, а на телефоне — `button:not(.clickable-icon).mobile-tap` с серым фоном и тенью; оба правила весом (0,2,1). Поэтому отступы, фон и тень каждого вида задаются на `button.tc-btn.is-<kind>` (0,2,1) и позже по файлу, а не на одиночном классе назначения. Ответ касанию — `button.tc-btn.mobile-tap` до правил видов. Тест: у правил, задающих `padding` кнопкам `.tc-btn`, вес не ниже (0,2,1). Проверка в тестовом Obsidian: каждой видимой кнопке дать `.mobile-tap`, отдельно телу `.is-tablet` — фон, тень и отступы не меняются (скрипт пробы описан в итоге этапа 2).

Классы назначения остаются только для позиции и того, что у кнопки своё: цвет плюса, размер стрелки месяца. Тест в `styles.test.ts` проверяет, что сброс кнопки и затемнение при нажатии объявлены только на `.tc-btn`.

**Кто переходит на кнопку:**

| Вид | Где сейчас |
|---|---|
| `round` | плюс (`PlusButton`), отмена (`UndoButton`). Плюс под пальцем (`PlusFloat`) и кольцо (`PlusRing`) — не кнопки, но берут вид `tc-btn is-round` без обработчика. Для этого есть функция `roundShape(parent, icon, tone)`. |
| `icon` | стрелки дня (`ColumnHeaders`), стрелки месяца (`MonthPicker`). Два одинаковых метода `arrow()` уходят. |
| `bar` | «влево» и «вправо», флажок, место на полосе быстрого ввода (`QuickBar`). Вид на десктопе по-прежнему через `.is-desk` на полосе. |
| `text` | Close, Edit, Cancel и Save на экране описания (`DescriptionSheet`). Два класса `tc-sheet-cancel/submit` → `tone: "plain" \| "strong"`. |
| `pill` | кнопки вопроса в меню (`askGroup`): Cancel и подтверждение, тон `danger` или `strong`. Кнопка «Create file» на экране «нет файла». |
| `swatch` | цвета уровней в настройках (`SettingsTab`). Становится настоящим `<button>`. Сейчас это `div` с `tabindex=0`: фокус есть, но Enter и Пробел не работают. Настройки — чужая страница Obsidian, без наших контейнеров. Поэтому сброс `button.tc-btn` должен действовать и там: правило не привязано к контейнеру. Каталог проверяет снимок настроек. |

Ручка разделителя (`Divider`) — не кнопка. Она становится `span` с `role="separator"`: тянут её за полосу, нажатие на неё ничего не делает. Это единственное изменение поведения этапа, и оно к лучшему: ручка больше не ловит фокус по Tab и не читается экранным диктором как кнопка без действия.

### 4. Мелочи из аудита

- **`FloatingCard` создаёт элементы через `el()`.** Сейчас — через `Object.assign(document.createElement…)`.
- **Точка «в работе» на таймлайне** рисуется через `showProgressDot` (`TaskCard.ts`). Сейчас она нарисована руками в `Timeline`.
- **`TaskCalendarView` прячет элемент классом**, а не `style.display = "none"`. `TaskMenu` — так же, вместо `style.visibility = "hidden"`. Классы получают префикс плагина, `tc-hidden` и `tc-invisible`, чтобы не пересечься с общими `is-hidden` Obsidian и других плагинов.
- **`el` импортируется под своим именем.** Сейчас в `Timeline`, `MonthPicker` и `Divider` он импортирован как `make`.

### 5. Тесты

- **`tests/ui/kit/Button.test.ts`.** Проверяет:
  - классы для каждого вида и тона;
  - `aria-label`;
  - иконка на месте;
  - `onPress` на клик;
  - `setOn`, `setOff`, `setHidden`.
- **`tests/ui/kit/icons.test.ts`.** Проверяет:
  - каждое имя рисуется;
  - в карте нет двух одинаковых путей под разными именами.
- **Старые тесты.** Те, что искали кнопки по старым классам, ищут по классу назначения. Классы назначения остаются.

## Не входит

- Окна, поднятые копии и подменю — этап 4.
- Любое видимое изменение.

Касание на master печатало пусто, но проба врала. Кнопки Obsidian плавно меняют фон (`transition`), и проба читала фон сразу, ещё старый. Теперь проба читает с выключенным `transition`. Так на master нашёлся живой баг: плитка меню под пальцем становилась прозрачной (`.tc-panel .tc-menu-tile`, вес (0,2,0)). Теперь она весит (0,2,1) и не меняется.

Отступления и решения:
- **Все кнопки плагина несут `tc-btn`.** Строки и плитки меню, строка «назад», «Refresh now», дни выбора даты — не виды кнопки: их API — этап 4. Они получили только класс `tc-btn`, их правила — `button` в селекторе и вес (0,2,1).
- **Видимые изменения, которых нет в каталоге:**
  - отступы на iPad;
  - касание плитки меню на телефоне;
  - цвет уровня в настройках на десктопе получил общий слой наведения, как все кнопки. Enter и Пробел на нём работают.
- **Кнопки, которые Obsidian рисует внутри описания** (копирование кода и т. п.), сброс больше не задевает: он не привязан к контейнеру. Теперь они выглядят как в заметке.
- **Вес наведения** стал (0,4,2) вместо (0,5,2): у ручки разделителя больше нет `:not()`. Три фона, которые его перевешивали, теперь заданы через `background-color`: место на полосе при открытой панели (2 правила) и выбранная плитка места. Без этого слой наведения пропал бы.
- **У `icon()` нет параметра `filled`.** Залитая часть — свойство самой иконки («В работе», «Готово»), вызывающим он не нужен. Иконка может состоять из нескольких штрихов: так нарисован плюс. Две линии с наложением в центре дают ровно прежние пиксели кнопки.
- **Видимый текст кнопки.** Без иконки — собственный текст кнопки, с иконкой — `span.tc-btn-label`. `aria-label` ставится, только если видимого текста нет или он задан отдельно от `label`. Поэтому атрибуты остались прежними.
- **Отдельных классов у кнопок экрана описания нет.** Close/Edit — `is-plain`/`is-strong`, правило `.tc-sheet-bar > button.tc-btn`. Вопрос — тон `danger` или `strong` у второй кнопки. `is-danger` у группы вопроса убран, CSS его больше не читал.
- **Ручка разделителя ушла в задачу 3, а не 4.** Без класса `tc-btn` она потеряла бы сброс, а это сдвиг пикселей между коммитами.
- Каталог и проба ищут кнопки экрана описания по `.tc-sheet-bar > .tc-btn`.
