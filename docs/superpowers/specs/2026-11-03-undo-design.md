# Отмена действий

Дата: 2026-11-03. Статус: спека, ждёт решения Макса по открытым вопросам.

## Что хотел Макс

Cmd+Z в календаре откатывает последнее действие: отметил задачу выполненной, удалил, перенёс — Cmd+Z возвращает как было.

## Решения Макса

- **Свой стек отмены плагина**, не история редактора Obsidian. Стек Obsidian есть только у открытого редактора файла и живёт, пока вкладка открыта; варианты «только пока файл открыт» и «держать файл открытым в скрытой вкладке» отвергнуты (03.11).
- Отмена работает на обеих платформах и при закрытом файле задач.
- Подтверждение перед Delete и Won’t do остаётся (отдельная работа, доски «Подтверждение удаления»): отмена его не заменяет.

## Мои решения

- **Что отменяется:** каждое действие пользователя в календаре, которое меняет файл задач: статус, удаление, перенос, перетаскивание, время, срок, приоритет, переименование, описание, секции, подзадачи, новая задача. Одно действие пользователя — один шаг отмены, даже если оно пишет в файл в два приёма.
- **Что не отменяется:** ручные правки файла в редакторе (у них своя отмена Obsidian), изменения через Sync с другого устройства, автоматический перенос задач при смене дня (`normalize`).
- **Повтор:** Cmd+Shift+Z возвращает отменённое. Новое действие очищает повтор.
- **Глубина** — 100 шагов. Стек в памяти, общий для всех вкладок календаря, пропадает при перезапуске Obsidian или плагина: после перезапуска отменять нечего. Хранить на диске не нужно — отмена нужна сразу после ошибки.
- **Где работает Cmd+Z:** когда в фокусе вкладка календаря и курсор не в поле ввода (в поле переименования и быстрого ввода Cmd+Z отменяет набор текста, как везде). В палитре команд — «Task Calendar: Undo» и «Task Calendar: Redo».
- **Файл изменился с тех пор** (ручная правка или Sync): отмена возвращает только то, что меняло само действие, и не трогает чужие правки. Если чужая правка задела те же строки, отмена не выполняется, шаг убирается из стека, а пользователь видит «Can’t undo: the tasks file changed».
- **Вместе со стеком отмена тоже действие:** после отмены лента и карточки обновляются, как после любого изменения файла.

## Как устроено

### Domain — `src/domain/TextPatch.ts` (чистый)

- `TextPatch.between(before, after)` — построчный diff (LCS; файл задач — сотни строк, этого хватает) в набор блоков: где, какие строки были, какие стали, плюс по 2 строки контекста вокруг.
- `patch.revert(current): string | null` — накладывает обратную правку на текущий текст: каждый блок ищется сначала на прежнем месте, потом по контексту; блок «стали» должен совпасть строка в строку. Не нашёлся хоть один блок — `null`, ничего не меняется (всё или ничего).
- `patch.apply(current)` — то же в прямую сторону, для повтора.

### Application

- `UndoHistory` (новый класс): два стека шагов `{ patch, label }`. `record(before, after, label)`, `undo()`, `redo()`, `canUndo`, `canRedo`, `onChange`. Отмена и повтор пишут в файл через тот же `TaskFileStore.write` атомарно: `revert` внутри `vault.process`.
- `TaskServiceImpl.mutate(operation, label)`: в `store.write` уже есть текст до и после — если они различаются, шаг записывается в `UndoHistory`. `normalize()` шаг не пишет. `label` — название действия для подсказки («Task deleted», «Marked done», «Moved to Tomorrow»).
- Одно действие из нескольких записей: `history.group(label, fn)` склеивает все записи внутри `fn` в один шаг. Вызывается из места, где UI делает два вызова сервиса подряд на один жест (проверить перетаскивание из таймлайна в список: `clearSlot` + `moveBefore`).
- `contracts.ts`: интерфейс `UndoService { undo(): Promise<UndoOutcome>; redo(): Promise<UndoOutcome>; canUndo(): boolean; canRedo(): boolean; onChange(listener): () => void }`, `UndoOutcome = { kind: "done", label } | { kind: "nothing" } | { kind: "conflict" }`. Это общий контракт: меняется вместе со всеми, кто сейчас работает над `mvp`.

### UI

- `TaskCalendarView` регистрирует в своём `scope` (Obsidian `Scope`, активен, пока вкладка в фокусе) `Mod+Z` и `Mod+Shift+Z`; если фокус в поле ввода, клавиши уходят полю.
- Команды плагина Undo/Redo в `main.ts` — для палитры и своих горячих клавиш.
- Способ отмены на телефоне и подсказка после отмены — по доскам (открытые вопросы).

### Тесты

- `TextPatch`: правка, вставка, удаление, перенос строки далеко вниз; отмена после чужой правки в другом месте файла; отказ при чужой правке тех же строк; повтор.
- `UndoHistory` + `TaskServiceImpl` на файле в памяти: каждое действие меню отменяется в точности до прежнего текста; новое действие очищает повтор; глубина 100; `normalize` шаг не пишет.

## Открытые вопросы (к Максу, доски на холсте)

1. **Отмена на телефоне.** Cmd+Z на iPhone нет. Вариант по стандарту iOS — плашка снизу после действия с кнопкой Undo, гаснет через несколько секунд. Нарисовать варианты: какая плашка, где (над переключателем колонок), после каких действий.
2. **Подсказка на Mac после Cmd+Z** — показывать ли, что именно отменилось (та же плашка), или достаточно того, что задача вернулась на место.
