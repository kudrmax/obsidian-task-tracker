# Пустая секция: бэкенд (domain + application)

Дата: 2026-11-05. Статус: черновик на проверку Максу. Основа: `2026-10-31-sections-design.md` (дальше «спека секций»), `2026-11-01-quick-add-design.md` (быстрый ввод), `2026-11-05-layers-7-sections-design.md` (блок 7, `ListView`). Где эта спека расходится со спекой секций, права эта. Вид (заголовок, плашка «No tasks», переключатель в поле) — дело доски и спеки UI; здесь только то, что отвечают domain и application.

Слова — как в спеке секций: **список** — `## Inbox | Backlog | Now | Soon`, **секция** — `### Имя` внутри списка, **группа** — секция или «No section». **Колонка** — то, что видно на экране: Inbox, Backlog, Soon (Soon без срока), колонка дня (сегодня — Now; будущий день — Soon с этим сроком и задачи Now с этим сроком; прошлый — без секций).

## 1. Что решил Макс

1. Пустая секция (`### Имя` без задач) может жить. Нормализация её больше не удаляет.
2. Секция уходит, только когда из неё **уносят последнюю задачу**: перетаскиванием, меню Section, удалением, Done, переносом на другой день, на таймлайн, и правилами нормализации, которые сами переносят задачу (правило 2 в Done, правило 3 Inbox → Soon, правило 4 Soon → Now, правило 5).
3. Секция, созданная пустой (руками в markdown или из поля), остаётся. Секция, где руками стёрли последнюю строку задачи, тоже остаётся: её никто не уносил.
4. Пустой заголовок `### No section` по-прежнему не держится.
5. Поле быстрого ввода получает переключатель «задача ↔ секция». В режиме секции Enter ставит `### Имя` ровно в место поля: середина группы — задачи ниже линии уходят в новую секцию; низ группы — секция пустая.
6. На экране пустая секция — заголовок и пунктирная плашка «No tasks». Бросок на плашку — `moveToGroup(key, list, name, null, date)`; тап по плашке — поле новой задачи в этой секции (`CreatePlace` kind `list`, `group: name`, `before: null`).

## 2. Правило «унёс последнюю — секция ушла»

### 2.1 Где живёт

Одно место: `TaskDocument`. Три метода, которые вынимают задачу верхнего уровня из её места, после своей работы смотрят на группу, откуда она ушла:

- `moveEntry(entry, section, position)`,
- `removeEntry(entry)`,
- `nestEntry(entry, parent, before)` (последнюю задачу секции вложили в задачу другой секции — секция тоже опустела).

Правило: если `entry` — задача верхнего уровня (`path` пуст), её группа — настоящая секция (`heading && name !== null`), и **после всей операции** (вынули и вставили) эта группа `blank` (под заголовком только пустые строки), — группа удаляется `deleteGroup`. Отсюда само собой:

- **Переход в ту же группу — не опустошение**: проверка идёт после вставки, задача уже снова в группе.
- **Подзадача не опустошает**: у неё `path` не пуст, а её задача остаётся в секции.
- **Секция с текстом без задач не удаляется**: она не `blank`.
- **Ручная правка не удаляет**: стёртая руками строка не проходит через эти методы.
- **«No section» с заголовком** этим правилом не удаляется (у неё `name === null`); её снимает нормализация (§3).

Номер группы до и после операции один и тот же: `moveEntry`, `removeEntry` и `nestEntry` заголовков не добавляют. Удаление идёт последним шагом метода, поэтому номера групп ниже сдвигаются только для вызывающего, который потом читает `groups()` заново (так и делают все нынешние вызовы: `intoGroup`, `mergeDuplicates`, `gatherAtStart`, `applyAll` по ключам «как прочитан»).

Решение агента: правило в документе, а не в `operations.ts` и не в нормализации, потому что через `moveEntry` идут и действия (`moveToGroup`, `createGroup`, `putOff`, `toList`, `toSoon`, `toEnd`, `placeOnTimeline` → правило 5), и все правила нормализации, которые переносят задачи (`gatherAtStart` — правило 2 и 4 без секции, `datedOutOfUndated` — правило 3, `intoGroup` — правило 4 в секцию, `misplacedOutOfGroups` — правило 5). Одно место — один механизм; ни одна новая операция не сможет его забыть.

### 2.2 Кто удаляет секцию другим способом (не меняется)

- `mergeGroup` (Remove section, Rename в имеющееся имя, правило 6) — заголовок уходит сам.
- `deleteGroup` — примитив, им пользуется правило из §2.1 и правило 8 для «No section».

### 2.3 Что разделение группы (§4) не делает

Разделение — отдельный примитив `splitGroup`, не `moveEntry`: исходная группа после него может остаться пустой (поле стояло над первой задачей секции — все её задачи ушли ниже нового заголовка) и **остаётся**, как если бы `### Имя` дописали руками под заголовком. Её никто не уносил: заголовок поделил группу.

## 3. Нормализация

- **Правило 8** сужается: удаляется только пустой заголовок «No section» (`index > 0`, `name === null`, `blank`). Настоящую секцию правило 8 больше не трогает. Функция переименовывается в `dropEmptyUngroupedHeading`.
- Правила 2–5, которые переносят задачи, удаляют опустевшие секции через `moveEntry` (§2.1). Пример спеки секций (§4: «правило 5 уводит единственную задачу, правило 8 удаляет пустой `### Вечер`») остаётся верным, только удаляет теперь правило 5 своим переносом.
- Правило 7 не меняется: оно смотрит на «No section» и верхний блок.
- Идемпотентность сохраняется: пустая секция — неподвижная точка всех правил.

Спека секций §4 правило 8 и пример под ним переписываются (§9).

## 4. Новая операция: секция из поля

### 4.1 Контракт

```ts
// contracts.ts — ОБЩИЙ КОНТРАКТ (CLAUDE.md: только со всей командой; отдельный коммит в начале ветки)

/** Where a section is written from the quick-entry field: a top-level place in a column that shows sections. */
export type SectionPlace = Extract<NewTaskPlace, { readonly kind: "list" } | { readonly kind: "day" }>;

interface TaskService {
  /**
   * The field switched to a section, Enter (empty sections spec §4). `### name` goes where the field stands: the tasks the
   * column shows below it in its group, in order, go into the new section, written right after that group; the tasks it does
   * not show stay. At the end of a group the section is written empty and stays. A blank name or the No section name writes
   * nothing; the group's own name writes nothing; a name the list has takes the tasks below to the end of that section.
   * One write, one undo step. Gives the section the tasks went to, or null when nothing was written.
   */
  createSection(name: string, place: SectionPlace): Promise<{ readonly list: GroupedList; readonly group: string } | null>;
}
```

Поле подзадачи, переключённое на секцию, встаёт на верхний уровень после всего поддерева своей задачи — это делает UI (оно же визуально переезжает, чтобы было видно, где ляжет заголовок), и в сервис приходит уже место верхнего уровня: `group` задачи и `before` — следующая видимая карточка верхнего уровня этой группы или `null`. Поле на таймлайне переключателя не имеет; колонка прошлого дня (`DayColumn.sections === false`) — тоже. Сервис на такое место (`dayColumn(date).sections === false`) отвечает `null`, ничего не пишет. Решение агента: сервис не принимает место подзадачи, потому что «следующая карточка после поддерева» зависит от колонки, а колонку знает только место верхнего уровня.

### 4.2 Что уходит в новую секцию

Колонка будущего дня и колонка Soon показывают только часть задач Soon. Правило — **«что видно ниже линии»**:

- Берётся группа колонки так, как её показывает экран (§5: `columnGroups` — тот же запрос, что строит `ListView`), с её видимыми карточками верхнего уровня в порядке экрана.
- Ниже линии — карточки от `before` (включительно) до конца этой группы на экране; `before === null` — ни одной.
- Они уходят в новую секцию в своём порядке. Скрытые в этой колонке задачи группы (у Soon: со сроком на другой день в колонке Soon; без срока или с другим сроком в колонке дня) **остаются в прежней группе**, на своих местах.
- Новая секция встаёт в файле **сразу после исходной группы** — после последней её строки, включая скрытые задачи.

Порядок на экране не ломается:

- **Эта колонка**: исходная группа показывает карточки выше линии, сразу под ней — новый заголовок с карточками ниже линии, дальше — следующие группы. Ровно то, что было на экране, с заголовком в месте поля.
- **Другие колонки того же списка** (Soon и другие будущие дни): в новой секции нет ни одной их задачи, а сама она не пустая в файле — они её не показывают (§5.1); их задачи исходной группы не двигались.
- **Сегодня (Now)**: колонка показывает все задачи Now, кроме стоящих на таймлайне; задачи со слотом в секциях не живут (правило 5), значит в «No section» остаются только они — их и так нет в списке.

Задачи Now с будущим сроком в колонке будущего дня: они стоят в группе «No section» выше задач Soon. Если линия прошла среди них, они ниже линии и уходят в новую секцию Soon, входя в Soon как при `moveToGroup` (срок — день колонки), впереди задач Soon, в порядке экрана. Решение агента: так секция на экране собирает ровно то, что было под линией; оставить их значило бы показать задачу, бывшую под линией, над новым заголовком.

Подзадачи едут со своими задачами.

### 4.3 Имя

| Имя | Что пишется | Почему |
|---|---|---|
| Пустое, из пробелов; отмена | ничего, `null` | как Rename и New section |
| Имя «No section» из настроек | ничего, `null` | решение агента: `### No section` в файле — это заголовок группы без секции (спека секций §3.2, правило 7), а не новая секция; запись вынула бы задачи ниже линии из их секции, а не завела бы секцию. Неожиданно и не то, что просили |
| Имя самой исходной группы | ничего, `null` | заголовок, который ничего не делит |
| Имя, которое в списке уже есть (секция H) | задачи ниже линии встают в конец H, на её месте; нового заголовка нет; ответ — H | правило 6 сливает во **первую** из двух; если H выше линии, результат тот же. Если H ниже, правило 6 потянуло бы H вверх к линии — решение агента: секции не прыгают, задачи идут к H. Реализация — `splitGroup`, затем `mergeGroup(S, H, "end")` до нормализации, чтобы исходная группа не исчезла (§2.3) |
| Новое имя | `### имя` в месте поля, ответ — эта секция | — |

Имя обрезается по краям (`trim`), как у `createGroup`. Секция-заготовка из поля встаёт в место поля, а не по порядку заготовок: место выбрал пользователь.

### 4.4 Домен

- `TaskDocument.splitGroup(section, index, name, moved: readonly TaskEntry[])` — одна перезапись: вынимает строки `moved` (с поддеревьями) из группы `index`, остальное (скрытые задачи, текст) остаётся; после последней заполненной строки группы вставляет `### name` и вынутые строки в их порядке. Пустые строки — как у `addGroup`/`moveGroup` (план сверит с их тестами пробелов). `moved` пуст — то же, что `addGroup(section, name, index + 1)`. Правила §2.1 не применяет.
- `queries.columnGroups(doc, column, today, boundary)` — группы колонки в порядке экрана: имя, список, номер группы в списке, видимые задачи верхнего уровня. Включает пустые секции (§5.1). Один запрос для `ListView` и для «что ниже линии» — один механизм.
- `operations.createSection(doc, column, group, before, name, groups, today, boundary)`: §4.2 и §4.3. Задачи другого списка (Now в колонке будущего дня) после `splitGroup` переносятся `moveToGroup` в новую секцию перед её первой задачей.

### 4.5 Сервис

`TaskServiceImpl.createSection`: пустое имя — `null` без записи. Иначе один `mutate`: разрешить место (как `resolve` для `list`/`day`; группа должна быть в файле, `before` — задачей этой группы, видимой в колонке, иначе `StaleTaskError`), `ops.createSection`, нормализация в той же записи. Ответ — список и имя секции после нормализации (`insertedSince` не нужен: имя известно). Ничего не изменилось — `mutate` не пишет и не кладёт шаг отмены.

### 4.6 Отмена

Одна запись — один шаг `UndoHistory` (так `mutate` уже работает): Undo после секции из поля возвращает и заголовок, и задачи на места одним шагом. Undo переноса, который удалил опустевшую секцию, возвращает её вместе с задачей — заплатка текста одна. Ничего нового в `UndoHistory` не нужно.

## 5. Экран: что отдаёт сервис

### 5.1 Где видна пустая секция

Группа колонки видна, если в ней есть задачи, которые колонка показывает, **или** она пустая секция: настоящая секция без единой задачи в файле (`entries.length === 0`).

| Колонка | Пустые секции какого списка |
|---|---|
| Inbox, Backlog | своего |
| Сегодня | Now |
| Soon | Soon |
| Будущий день | Soon (в файле у пустой секции нет даты, поэтому она во **всех** колонках будущих дней и в колонке Soon сразу) |
| Прошлый день, таймлайн | нет: секций там нет, как сейчас |

- Секция Soon, у которой есть задачи, но не на этот день, — не пустая, в колонке не видна (как сейчас): иначе каждая секция завтрашнего плана стояла бы плашкой «No tasks» в Soon и во всех остальных днях.
- Как только в пустую секцию Soon бросили задачу на завтра, секция перестаёт быть пустой и пропадает из Soon и других дней.
- Секция только с текстом (раньше «не трогается и не показывается»): теперь видна как пустая, с плашкой. Решение агента: пустые секции стали законными, а текст под заголовком — не задача; спрятать её значило бы держать в файле секцию, в которую нельзя ничего бросить.
- «No section» без задач не видна никогда (плашки у неё нет; её пустой заголовок снимает правило 8).

### 5.2 Заголовки и `ListView`

`ListView` — из блока 7 (общий контракт). Эта ветка либо идёт после блока 7, либо вводит `ListView` ровно в его форме, и блок 7 строится на нём. Добавляется одно правило в комментарии контракта:

```ts
// contracts.ts — ОБЩИЙ КОНТРАКТ
export interface ListView {
  /** A visible section in the column, an empty one included. */
  readonly showsHeaders: boolean;
  /**
   * The column's groups in screen order. A group with no items is an empty section (its heading and the No tasks plate):
   * a section with no task in the file. A group with tasks for other days only, and No section without tasks, are left out.
   */
  readonly groups: readonly { readonly name: GroupName; readonly items: readonly TaskItem[] }[];
}
```

Решение агента: отдельного флага `empty` нет: `items: []` бывает только у пустой секции, другие группы без карточек `ListView` не отдаёт. Признак, который всегда равен `items.length === 0`, был бы вторым источником одного факта.

- `showsHeaders` — есть хоть одна видимая настоящая секция, пустая тоже. Значит, одна пустая секция включает заголовки, и задачи без секции получают заголовок «No section» над собой (спека секций §5.1 остаётся верной: пустая секция — видимая группа).
- Зазоры (`listGaps`) уже дают пустой группе один зазор «конец группы» — это плашка; бросок на неё — `moveToGroup(key, list, name, null, date)`. Тап по плашке — `createInPlace(…, { kind: "list" | "day", group: name, before: null })`. Обе ручки есть, новых не нужно.
- `sectionChoices` (блок 7) включает пустые секции списка: в них можно перенести задачу из меню.

### 5.3 Перестановка пустой секции

Пустую секцию переставляют, как любую (решение Макса): долгое нажатие на заголовок, `moveGroup(list, name, place)`. Внизу она стоять не обязана: в файле `### Имя` просто стоит перед следующим заголовком без задач под собой.

- `TaskDocument.moveGroup` уже переносит пустой блок: `contentOf` у `blank` блока пуст, переносится одна строка `### Имя`, а его пустые строки остаются на старом месте (`apart`) — вокруг ничего не склеивается. План закрепляет это тестами, ничего не меняя в коде, если они проходят.
- Правило §2.1 перестановку не касается: `moveGroup` задачи не вынимает. Нормализация пустую секцию больше не снимает (§3), поэтому после перестановки она не исчезает.
- Две пустые секции подряд (`### A` сразу над `### B`) — обе на месте; правило 6 сливает только одноимённые.
- Пустая секция, поставленная выше «No section» (`moveGroupTo` с `before: null`): задачи без секции уходят под заголовок `### No section`, как для любой секции; если задач без секции нет — заголовок «No section» не пишется (правило 7 и правило 8 для пустого «No section»).
- `spacedHeadings` трогает только строки под заголовками списков `##`: пустая секция первой строкой списка получает над собой одну пустую строку, как любая; пустая секция последней строкой списка не съедает пустую строку перед следующим `##` (`cutOf` последнего блока оставляет её). Тест — на каждом из краёв.
- Переименование пустой секции — `renameGroup`, удаление — Remove section (`mergeGroup` пустого блока в «No section»: переносить нечего, заголовок уходит).

## 6. Что меняется в контрактах

Общий контракт `src/application/contracts.ts` (только со всей командой, отдельный коммит в начале ветки):

1. `SectionPlace` и `TaskService.createSection` (§4.1).
2. `ListView` — правило пустой группы и `showsHeaders` с пустыми секциями (§5.2); если блок 7 ещё не влит, сам `ListView` в форме блока 7.
3. Комментарий над `TaskService`: «A call that takes the last task out of a section takes the section away; a section left empty any other way stays.» Комментарии `moveToGroup` (цель — пустая секция: `before` null), `removeGroup` и `normalize` — без изменения смысла.

`src/settings.ts` не меняется.

Не контракты: `TaskDocument` (`moveEntry`, `removeEntry`, `nestEntry` — §2.1; новый `splitGroup`), `normalize.ts` (правило 8), `queries.ts` (`columnGroups`), `operations.ts` (`createSection`), `TaskServiceImpl` (`createSection`, построение `ListView` из `columnGroups`), `ui/listGroups.ts` (раскладывает готовые группы, пустая группа — заголовок и плашка; это UI-спека).

- `moveEntry` внутри той же секции (в том числе последней и единственной) — секция на месте.
- `moveEntry` подзадачи из секции — секция на месте.
- `removeEntry` последней — секция ушла; `nestEntry` последней под задачу другой секции — ушла, под задачу той же — на месте.
- Секция с текстом: унесли последнюю задачу — секция с текстом на месте.
- `### No section` без задач после переноса не удаляется документом (это делает правило 8).
- `moveToGroup` в пустую секцию (`before` null) — задача в ней; в колонке будущего дня — Soon со сроком дня.
- `createGroup` из пустой секции, Remove section и Rename пустой секции.
- Перестановка пустой секции (`moveGroupTo`, затем `normalize`): в середину, наверх (выше «No section» — с задачами без секции и без них), в конец списка, в конец последнего списка файла; две пустые подряд; результат после нормализации — неподвижная точка, пустые строки (`blanks`) как у непустой секции, секция не исчезла и не слилась с соседней.
- `createSection`: середина группы — задачи ниже линии в новой секции, сразу после группы; линия над первой задачей секции — исходная секция остаётся пустой; низ группы — пустая секция; низ последней группы — пустая секция в конце списка; середина «No section» наверху — новая секция первым `###`; будущий день: скрытые задачи Soon (без срока, другой день) остаются в исходной группе и порядок колонки и колонки Soon прежний; Now-задачи будущего дня ниже линии уходят в Soon со сроком; пустое имя, «No section», имя исходной группы — документ тот же; имя существующей секции выше и ниже линии — задачи в её конец, секции не двигаются; подзадачи едут с задачами; заготовка встаёт в место поля.

**Domain, `normalize.test.ts`:**

- Пустая секция (`### X` и пустые строки) — неподвижная точка в каждом из Inbox, Backlog, Now, Soon.
