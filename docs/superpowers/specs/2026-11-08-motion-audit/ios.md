## Корень A. Идентичность карточки — это текст её строки, а ядро не говорит, какая строка какой стала

**Где.** `apple/Core/Sources/Core/BoardSnapshot.swift:470-476` (`Painter.identity`: `"\(item.list)|\(item.key.raw)"`)
→ `BoardCard.id`, по нему `ForEach` в `ListColumn.swift:31` и `TimelineColumn.swift:99`. `raw` — вся строка файла
со статусом `[ ]/[x]/[/]`, префиксом приоритета, метками, `📅`, `📌 время`, `🔁`, `📁` (свёрнуто). Любая правка
строки = новый `id` = SwiftUI уничтожает вью карточки (UIKit `CardControl` вместе с её `MenuOpener`) и вставляет
новую. Меню задачи при этом закрывается анимацией к превью `self.content` уже удалённого контрола
(`CardButton.swift:206-209`, `325-327`).

**Почему корень, а не место.** Ядро (`core/`) не выдаёт устойчивого id задачи и не возвращает из записи, какой
ключ стал каким (`docs/door.md` — «a key names a task as read»; `BoardModel.write` результат записи выбрасывает).
Swift вынужден угадывать идентичность по тексту — и угадывает неверно ровно тогда, когда задача меняется. Это класс:
каждый пункт меню, который меняет строку.

**Задеты:** Done / In Progress / Won't Do, p1/p2, метки, Today/Tomorrow/Pick a Date, Repeat, Reminder, Rename, свёртка
подзадач (📁 в строке), перенос в календарь (добавляется `📌`), перенос из календаря в список (снимается `📌`).

| Находка | Шаги | Что дёргается (замер) |
|---|---|---|
| A1. Приоритет из меню | Тап по «Разобрать почту» → p1 (запись `prio3`) | 524–528: меню уходит, на месте карточки **дыра**, превью-призрак «Разобрать почту» (без цвета) садится на 15–25 pt ниже своего места поверх «Обсудить с командой»; 529–534: новая красная карточка **проявляется** (кроссфейд ~100 мс), призрак гаснет. Вместо «карточка перекрасилась» — исчезла, призрак уехал, появилась новая. |
| A2. Свернуть подзадачи (тап по счётчику) | Тап по 0/2 у «Созвониться с врачом» (`fold`) | 22–28: родитель **полупрозрачный** (кроссфейд старой и новой вью, т.к. в строку пишется 📁), одновременно ряды едут вверх. |
| A3. Rename из меню | Тап → Rename (`sub`) | 586–590: превью меню улетает на строку ниже (на «Обсудить…»), на месте карточки пусто 4–6 кадров, потом появляется поле. |
| A4. Перенос в календарь | см. C2 | карточка в календаре — новая вью (`📌` в строке), поэтому прилетевшее превью не «становится» ею, а висит отдельно. |

**Сопутствующее (тот же корень, производительность).** `TaskItem.==` сравнивает весь JSON, включая `key.index`
(`BoardModels.swift:126`), а `CardControl.Look` включает весь `BoardCard` (`CardButton.swift:56-62`): вставка одной
строки сдвигает `index` у всех ниже → каждая карточка ниже пересобирает `UIHostingConfiguration` на каждом чтении.
`snapshot` строит меню для каждой карточки на каждом чтении (`BoardSnapshot.swift:318-321`).

## Корень B. Экран перерисовывается заменой всего снимка под одной `withAnimation`, а список — голый VStack из UIKit-карточек

**Где.** `BoardModel.show` (`BoardModel.swift:206-223`): `withAnimation(.snappy) { snapshot = read }` — весь экран
из ядра заново, SwiftUI сам диффит по `id`. Список — `ScrollView { VStack { ForEach } }` (`ListColumn.swift:29-55`)
без своих переходов вставки/удаления; ветки подзадач (`branch`) и счётчик — данные строки, а не анимируемая геометрия.
Вставляемые/удаляемые карточки получают переход по умолчанию (opacity) и стоят на конечном месте, а соседи, которые
ещё едут, рисуются поверх.

| Находка | Шаги | Что дёргается (замер) |
|---|---|---|
| B1. Удаление строки (Done у подзадачи) | Тап по подзадаче → Done (`done2`, светлая) | 19: счётчик 0/2→0/1 **мгновенно**, раньше движения; 23–31: строка ниже **наезжает поверх** исчезающей «Найти номер клиники» (текст обрезан снизу, не гаснет), 29–31: изгиб ветки «последней» подзадачи переключается скачком. |
| B2. Вставка строки (правка файла снаружи / после Sync) | Дописать строку в файл (`ext`) | 1,2 с от записи до отрисовки (settle 1 с, по замыслу); 79–85: новая карточка проявляется **под** съезжающей «Обсудить с командой» — две капсулы перекрыты ~9 кадров. |
| B3. Свёртка | `fold` 22–28 | раскрытые подзадачи гаснут, а «Записаться в барбершоп» едет вверх **поверх** них. |

Корень в коде — модель «перечитал файл → отдал весь снимок в `withAnimation`»: на ней не построить правильные
вставки/удаления (List/UICollectionView diffable делают это сами: удаляемая строка уходит под соседей, ветки и
разделители анимируются как геометрия).

## Корень C. Перенос живёт в двух местах, а куда летит превью, Swift считает сам по старой геометрии

**Где.** Состояние переноса: SwiftUI-модель (`carry`, `gap`, `settling`, `landing` в `BoardModel.swift:511-518`)
и UIKit-сессия drag/drop с её превью (`CardControl`, `BoardDrop`). Цель полёта превью — прямоугольник, который Swift
вычисляет сам до записи: `landingRect`/`gapRect` (`BoardModel.swift:762-792`, по геометрии, снятой до раздвижки) и
`landOnCalendar` (`BoardModel.swift:869-887`, по минуте линии), → `BoardDrop.previewForDropping`
(`BoardDrop.swift:116-120`). Конец переноса — по первому чтению после записи, без перехода и без синхронизации с
аниматором drop (нет `dropInteraction(_:item:willAnimateDropWith:)` с `addCompletion`): `show(... animated: false)`
→ `endCarry()` → `CardControl.carried = false` → `alpha = 1` (`CardButton.swift:90-98`, `278-280`) — карточка видна,
пока превью ещё летит. Где ядро на самом деле нарисует карточку (стопка, «прошедшее под now», другая секция) — Swift
не знает до чтения.

| Находка | Шаги | Что дёргается (замер) |
|---|---|---|
| C1. Drop внутри списка | Долгое нажатие «Сделать конспект» → вверх между «Записаться…» и «Полить цветы» (`drag1`) | 637–642: ряды начинают расступаться (`settling`, snappy 0.25 с) и успевают на 14 pt; 643: мгновенная отрисовка записи — ряды **прыгают на 16 pt за кадр**, потом 644–649 доползают ещё 5 pt (две анимации подряд); 643–651: карточка уже на новом месте, а превью садится **на 15 pt выше** и съезжает вниз — **двойная карточка** (наложенный текст) ~150 мс. |
| C2. | C3. Перенос секции | Долгое нажатие «Afternoon» → вверх (`sect`) | 142: весь список **переставляется за один кадр** (разница кадра 26,8 — максимум аудита), ничего не едет; превью секции сжимается на месте (`landSection` возвращает nil, `BoardModel.swift:573-592`), на 144 двойной заголовок «Afternoon». |
| C4. Подъём секции | там же | 72–80: при каждом подъёме **всплывает контекстное меню** «Rename / Remove Section» и исчезает, когда палец пошёл: на заголовке одновременно `.contextMenu` и `.onDrag` (`ListColumn.swift:301-309`, `326-331`). 44–68: секция сворачивается ещё до подъёма, заголовки «Afternoon» и «Evening» **наложены** друг на друга ~0,4 с. |
| C5. Плюс в список | Тянуть + и отпустить между карточками (`plus`) | 83–101: плюс **улетает домой**, хотя поле открывается (плюс приравнен к отмене, `land` возвращает nil для плюса); поле открывается только на 104 (≈0,4 с после отпускания); 107–122: летящий плюс **виден поверх полосы над клавиатурой** — таб-бар уходит своим `.move+opacity`, а `PlusButton` своей UIView-пружиной (`PlusButton.swift:119`, `235`). |

даёт призрак или двойную карточку. C1 и C2 — разные проявления; C3 — тот же механизм без цели вовсе.

## Отдельные находки (свой корень)

## Проверено и чисто

- Открытие меню задачи тапом: системная анимация роста, ≈0,5 с, без скачков (`tapmenu` 170–199). Открытие и закрытие
  подменю Section — системное (`prio` 470–500, 1006–1036).
- Подъём карточки долгим нажатием: подсветка в кадр нажатия, системный подъём, при первом движении пунктирное место
  и линия drop без мигания (`drag1` 506–570).
- Тап по вкладке Soon: лента едет одной кривой 4, 9, 13, 15, 15, 15, 14, 13 … 1, 0 pt/кадр, без рывка и отката (`tabs2`).
- Свайп ленты вправо (Today→Soon): одна страница, без пружины (`tabs` конец).
- Меню ⋯ (Search / Select Tasks / Calendars / Settings): системное.
- Лист Capture: открытие, переключение сегмента, закрытие свайпом; задача появляется на доске под листом, при закрытии
  листа доска не дёргается (`cap3`).
- Линия времени при переносе над календарём идёт по шагу сетки, смена 22:15→22:00 без мигания (`tl` 98–107).
- Чтение после своей записи быстрое (drop → новый кадр за ~100 мс, без ожидания settle).

- Смена дня стрелками и тап по «Today» (стрелки не работают, F2) — E3 только по коду.
- Поиск и переход к найденному, Settings и их переходы, экран задачи на весь экран, разделитель колонок, Undo,
  долгое нажатие на пустой календарь, плюс на календарь и на ×, кнопка Sync.
- Свайпов по карточкам в приложении нет (`swipeActions` нигде не используется).

## Сводка корней

1. **A — идентичность = текст строки; ядро не сообщает, какая строка какой стала после записи** (`Painter.identity`,
   контракт двери). Любая правка задачи из меню = уничтожение и новая вью + призрак меню. Нужен устойчивый ключ:
   либо ядро выдаёт id задачи на время сессии / возвращает из записи соответствие старый→новый ключ, либо фронтенд
   переносит идентичность по этому ответу. Это вопрос к backend.
2. **B — экран = замена всего снимка под одной `withAnimation`, список = VStack из UIKit-карточек** без правильных
   переходов вставки/удаления; ветки и счётчики — не геометрия.
3. **C — перенос в двух местах (SwiftUI-модель + UIKit-сессия), цель полёта превью угадывает Swift по старой
   геометрии, конец переноса не привязан к завершению анимации drop.** Даёт двойную карточку, призрак на 1 с,
   перестановку секции одним кадром, плюс поверх полосы.
