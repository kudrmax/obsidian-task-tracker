# Task Calendar: повторяющиеся задачи (issue #27)

Дата: 2026-11-04. Статус: поведение согласовано с Максом 04.11, вид — по доскам страницы холста «Повторы #27» (когда будут утверждены, их раздел встанет в `docs/design/README.md`; где доски и спека расходятся, правы доски). Основа: `docs/superpowers/specs/2026-10-30-task-calendar-design.md` (дальше «основная спека»), спека быстрого ввода `2026-11-01-quick-add-design.md`, спека секций `2026-10-31-sections-design.md`.

## 1. Зачем

Еженедельное и ежедневное сейчас заводится заново каждый раз. Нужно, чтобы после Done следующий раз появлялся сам.

Дела бывают двух видов:

- **По расписанию** — привязаны к дню недели или числу: зал по Пн, Ср, Пт; оплатить счёт 5-го; созвон раз в 3 недели по пятницам.
- **От последнего раза** — постричься, полить цветы, позвонить бабушке: следующий раз считается от дня, когда сделал. Сделал позже — следующий раз сдвинулся сам. Это родной для системы без просрочки повтор: пропущенные разы не копятся.

## 2. Цели, не-цели, анти-цели

**Цели**

- Повтор задаётся при вводе задачи (кнопка в полосе рядом с флажком) и у готовой задачи (строка Repeat в меню).
- После Done на месте задачи встаёт одна копия со следующей датой.
- Минимум видов повтора, покрывающий большинство случаев (решение Макса): «каждые N дней / недель / месяцев», у недель — выбранные дни недели; и «через N дней / недель / месяцев после Done».
- Телефон и Мак.

**Не-цели** (решение Макса и моё)

- Будущие повторы заранее по дням не расставляются: видна только ближайшая копия.
- Время у копии (решение Макса): копия всегда без времени, только со сроком. Время ставят перетаскиванием на календарь, как у любой задачи.
- Редкие правила: «последняя пятница месяца», исключения дат, конец повтора по дате или числу раз.
- Напоминания.
- Повтор у подзадачи (моё решение): повторяется задача верхнего уровня целиком, со своими подзадачами.

**Анти-цели**

- Состояние вне файла. Повтор — поле строки, как срок и время; плагин выключили — строка осталась читаемой.
- Копилка пропущенных раз. Копия всегда одна.
- Своя логика переноса для копий: копия — обычная задача со сроком, дальше её ведут правила основной спеки §4.4.

## 3. Модель

### 3.1 Поле в строке

Повтор — поле в конце строки, как `📅` и `⏰`, в любом порядке с ними. Эмодзи в настройках, по умолчанию `🔁`. Текст правила — по-английски, читается глазами и правится руками:

```
- [ ] Зал 📅 2026-11-09 🔁 every week on Mon, Wed, Fri
- [ ] Созвон 📅 2026-11-06 🔁 every 3 weeks on Fri from 2026-11-06
- [ ] Оплатить счёт 📅 2026-12-05 🔁 every month on the 5th
- [ ] Отчёт 📅 2026-12-31 🔁 every 2 months on the 31st from 2026-10-31
- [ ] Полить цветы 📅 2026-11-07 🔁 every 3 days from 2026-11-04
- [ ] Постричься 📅 2026-11-25 🔁 every 3 weeks when done
```

Грамматика (единица — `day(s)`, `week(s)`, `month(s)`, N ≥ 1, `every 1 week` пишется `every week`):

- По расписанию: `every [N] days`, `every [N] weeks on <дни>`, `every [N] months on the <число>`, у N > 1 в конце `from YYYY-MM-DD` — день, от которого идёт счёт (без него «каждые 3 недели» нельзя отличить от сдвинутых на неделю, ведь срок невыполненной задачи каждое утро становится сегодняшним, §4.4 правило 1). Дни — `Mon … Sun` через запятую, в порядке недели. Число — `1st 2nd 3rd 4th … 31st`.
- От последнего раза: `every [N] days|weeks|months when done`.
- Строка, которая не разбирается этой грамматикой, остаётся текстом задачи (как неизвестные хвосты сейчас).

Модель задачи получает поле `repeat: Repeat | null`. `Repeat` — доменный объект с методом `next(taskDate, doneDay)`.

### 3.2 Следующая дата

«Дата задачи» — срок, иначе дата слота, иначе нет.

- **Каждые N дней**: дни `from + kN`; следующая — первая такая строго позже max(сегодня, дата задачи).
- **Каждые N недель, дни D**: недели с понедельника; подходят недели `неделя(from) + kN`, в них дни D; следующая — первая такая строго позже max(сегодня, дата задачи). При N = 1 подходит каждая неделя.
- **Каждые N месяцев, число d**: месяцы `месяц(from) + kN`, в них число d, а в коротком месяце — его последний день (31-е в ноябре — 30-е); следующая — первая такая строго позже max(сегодня, дата задачи).
- **Через N после Done**: сегодня + N дней / недель / месяцев (месяц — по календарю, с тем же правилом последнего дня).

«Сегодня» — по началу дня из настроек (основная спека §4.5).

### 3.3 Что делает Done

Done у задачи с повтором — один шаг (одна запись файла, один шаг отмены):

1. Задача отмечается `[x]` и уходит в Done, как сейчас, но **без поля повтора**: в Done остаётся история, и правило ниже не сработает на ней второй раз.
2. Копия: тот же текст, приоритет, описание (строки без чекбокса), подзадачи — все снова `[ ]` (у `[x]`, `[/]`, `[-]` статус сброшен) и без своих сроков и слотов: они живут в день копии (моё решение; иначе прошлый слот подзадачи правило 1 превратило бы в сегодняшний срок). Срок — следующая дата (§3.2), слота нет, поле повтора то же. `from` не меняется.
3. Копия встаёт в конец Soon, в секцию с тем же именем, что была у задачи (секция заводится в конце Soon, если её нет; без секции — в «No section»). Оттуда в свой день правило 4 основной спеки забирает её в Now в ту же секцию: «Morning» каждый день возвращается в «Morning».

То же делает нормализация, если `[x]` поставили руками в markdown (основная спека §4.4, правило 2): задача с повтором в Inbox, Backlog, Now или Soon, отмеченная `[x]` или `[-]`, уходит в Done без повтора, а копия встаёт по пунктам 2–3. Правило идемпотентно: у ушедшей в Done строки поля нет. Два устройства могут сделать копию дважды до синхронизации — тот же принятый риск, что у остальных правил.

### 3.4 Won’t do и Stop

- **Won’t do** (решение Макса): пропущен только этот раз. Задача уходит в Done как `[-]` без повтора, копия встаёт, как после Done. У повтора после Done счёт от сегодня.
- **Stop** (решение Макса): четвёртая плитка в ряду статуса меню, только у задачи с повтором. Закрывает задачу как Done (`[x]`, галка в Done), без повтора, **копии нет**. Перед действием — вопрос на месте ряда, как у Won’t do («Stop “название”?», кнопки Cancel и Stop), потому что заканчивает все будущие разы (моё решение). Отменяется кнопкой отмены, как любое действие.
- **Delete** удаляет задачу с повтором, копии нет.
- Убрать повтор, не закрывая задачу, — в панели повтора (§4.2).
- Вернуть сделанный раз — только кнопкой отмены: она убирает и отметку, и копию. Если галку снять руками в markdown, задача в Done просто снова открыта и без повтора, копия остаётся (моё решение): связь между задачей и копией хранилась бы вне строки, а в интерфейсе выполненные задачи не открываются.

### 3.5 Повтор у задачи без даты

- По расписанию: задача получает срок — первый подходящий день не раньше сегодня (`from` — этот же день). Задача из Inbox или Backlog при этом уходит в Soon или Now по правилам §4.4: повтор по расписанию значит, что у дела есть день.
- После Done: срока не получает, стоит, где стояла; после первого Done копия получит сегодня + N.
- Задача со сроком сохраняет свой срок, даже если он не попадает в расписание (Зал в четверг, повтор Пн, Ср, Пт): следующий раз — по расписанию. `from` — срок задачи.

## 4. Интерфейс

Вид — по доскам страницы «Повторы #27». Здесь — что есть и как себя ведёт.

### 4.1 Где ставится

- **Быстрый ввод**: кнопка повтора в полосе над клавиатурой между флажком и кнопкой места, в капсуле десктопа — там же. Без повтора — контур, с повтором — подсвечена. У поля подзадачи и у поля на календаре её нет.
- **Меню задачи**: в группе правки строка Repeat (иконка повтора), справа значение коротко («Mon, Wed, Fri», «Every 3 weeks after done»). Её нет у подзадачи и у выполненной задачи. Открывает панель повтора на месте меню, как Pick a date.
- **Ряд статуса меню**: у задачи с повтором четыре плитки в один ряд — Done, In progress, Won’t do, Stop (решение Макса).

### 4.2 Панель повтора

Одна и та же из полосы, капсулы и меню. Ширина 300, вид панели меню.

- Наверху переключатель двух видов: **Schedule** и **After done**.
- Шаг: «Every N» с кнопками − и + и единица из трёх: days, weeks, months.
- У Schedule + weeks: ряд дней недели Mon…Sun, можно отметить несколько, хотя бы один отмечен. По умолчанию — день недели даты задачи (без даты — сегодняшний).
- У Schedule + months: подпись, какого числа (число даты задачи, без даты — сегодняшнее).
- Внизу у задачи с повтором строка «Remove repeat».
- Значение применяется сразу, как в панелях приоритета и места; панель закрывается тапом мимо.

Вид — вариант А «всё в одной панели» (решение Макса от 05.11), подробно — раздел «Повторы» в `docs/design/README.md`. По умолчанию при первом открытии: Schedule, Every 1, weeks, день недели даты задачи.

### 4.3 Карточка

На карточке задачи с повтором — значок повтора в колонке даты, сразу после числа, месяц под ними; без даты в колонке только значок (вариант 2, решение Макса). В списке; на таймлайне метки нет — доски её не рисуют. Копия в Done метки не несёт.

## 5. Слои

- `src/domain`: `Repeat` (разбор, запись, `next`), поле в `TaskLine` (срез с конца тела, как у срока и слота), правило нормализации и операции «Done с повтором», «Won’t do с повтором», «Stop», «поставить / убрать повтор» в `operations.ts`.
- `src/application/contracts.ts`: в представлении задачи — повтор для UI (вид, N, единица, дни, число) и его короткая подпись; команды `setRepeat`, `removeRepeat`, `stop`. Это общий контракт — меняется только в этой ветке вместе со всем остальным.
- `src/settings.ts`: эмодзи повтора рядом с эмодзи срока и времени (общий контракт, как выше).
- `src/ui`: кнопка в полосе и капсуле, строка меню, плитка Stop и её вопрос, панель, метка на карточке.
- `docs/plugin/`: не меняется — ничего руками настраивать не нужно.
