# Описание задачи

Дата: 2026-11-01. Дизайн принят Максом 01.11 (вариант А), доски `docs/design/canvas/Desc*.dc.html`, раздел «Описание задачи» в `docs/design/README.md`. Где этот документ и дизайн расходятся, прав дизайн.

## Зачем

К задаче часто нужно приложить то, что не нужно, пока смотришь на список: цитату сообщения, ссылку, детали. Это нужно, только когда с задачей работаешь, и тогда — спокойно прочитать целиком.

## Что это в файле

Описание задачи — её вложенные строки без чекбокса, на любой глубине. Они могут идти вперемешку с подзадачами:

```
- [ ] Задача 1
	- Описание её
	- Ещё её описание
	- [ ] Задача 2 (подзадача)
		- Описание подзадачи
	- Снова описание задачи 1
```

Описание задачи 1 — строки 2, 3 и 6; строка 5 — описание задачи 2. Строки, которые лежат под строкой подзадачи (глубже неё), — её описание. Строка с чекбоксом где угодно под задачей — подзадача, как и сейчас (даже если она глубже строки описания).

Пустых строк в описании нет: пустая строка, как и раньше, кончает задачу.

## Что видно

- Карточка задачи с описанием (в списке, на таймлайне, копия над меню, под пальцем) показывает значок описания в одном столбике со счётчиком подзадач.
- Тап по задаче с описанием открывает меню, а над задачей — начало описания (панель). Тап по панели — экран описания; ссылка в панели открывается сразу.
- Экран описания: название и описание целиком. Edit или тап по тексту — правка в редакторе Obsidian. Save записывает, Cancel — нет.
- У задачи без описания в меню строка Add description: экран описания сразу в правке.
- Текст описания везде рисует Obsidian: шрифт, интервалы, маркеры, отступы, цитаты, ссылки — из его настроек и темы.

## Запись

- Описание показывается как Markdown: строки описания в порядке файла, со сдвигом, общим для них, снятым (первый уровень — без отступа). Строки подзадач и их описаний в него не входят.
- Save с тем же текстом ничего не пишет. Изменённое описание встаёт одним куском сразу под строкой задачи, перед подзадачами; строки, шедшие вперемешку с подзадачами, переезжают в этот кусок (решение Макса от 01.11). Каждая строка получает отступ, который у описания уже был, иначе отступ подзадач этой задачи (тот, что у её подзадач, иначе на шаг глубже задачи, как у Add subtask), плюс свой относительный. Пустые строки отбрасываются. Пустое описание убирает все строки описания.
- Правка проверяет, что задача на месте (`StaleTaskError`, как все действия).

## Контракт (`src/application/contracts.ts`)

- `TaskItem.description: string | null` — описание как Markdown, null без описания.
- `TaskService.setDescription(key, markdown)`.

Изменение контракта аддитивное; параллельные ветки (quick-add, task-links) его не трогают.

## Как сделано (решения разработчика)

- Домен: `TaskDocument` знает, какие строки детей задачи принадлежат подзадачам; `descriptionOf(entry)` и `setDescription(entry, lines)` работают с остальными.
- Чтение: `MarkdownRenderer.render` в контейнер с классом `markdown-rendered`; путь источника — файл задач, так что `[[ссылки]]` и картинки разрешаются как в нём. Клик по ссылке — как у ссылок в названии (`openLink` вида): заметка в новой вкладке, адрес в браузере.
- Правка: редактор Markdown Obsidian (тот же, что в заметке, Live Preview) — общий класс `EmbeddedEditor` с полем названия задачи (`MarkdownTitleField`, ветка task-links): конструктор берётся у редактора встраиваемой заметки (`embedRegistry`), внутренний путь Obsidian. Пока в нём курсор, он — активный редактор вида, поэтому панель Obsidian над клавиатурой и его команды работают с ним. Escape — Cancel, Enter — новая строка.
- Add description открывает редактор с одним пустым пунктом `- `; такой пункт при сохранении — пустое описание.
- Панель над задачей — ещё одна часть `Overlay`, как копия карточки и панель меню.
- Цвета и размеры плагина — токены `styles.css`; у текста описания своих токенов нет, кроме размера в панели.

## Не делаем

- Описание при создании задачи (экран задачи не меняется).
- Показ описания в уведомлениях Scriptable.
